# Coding interview — question set

Default length: 4 questions (one small coding problem with follow-ups, plus technical discussion).
Score areas (use these names exactly):

- `problem solving`: clarifies the problem, finds an approach, handles edge cases
- `code`: correct, readable code or precise pseudocode in the answer
- `complexity`: states time and space cost and how to improve it
- `communication`: explains the thinking while working, not only the result
- `stack knowledge`: depth on the languages and tools the posting names

Questions (adapt to the posting's language and level; one per reply):

1. A small problem with a clear input and output, for example: given a list of log lines with
   timestamps and user ids, return the users active in every hour of a day. Ask the user to state
   the approach first, then write the code.
2. Follow-up on the same problem: the edge cases, then the time and space complexity.
3. Follow-up: the input no longer fits in memory, or arrives as a stream. What changes?
4. How would you test this function? Which cases first?
5. A discussion question on a tool from the posting: how it works under the hood, when not to use it.
6. Describe a bug you tracked down that took more than a day. How did you find it?

Rubric: 5 correct, efficient and well explained; 4 correct with small gaps; 3 works with hints or
misses an edge case; 2 partial or wrong approach; 1 no workable approach.
